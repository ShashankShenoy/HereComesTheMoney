# Bank officer skill

Use list_scoped_accounts and search_customers for authorized work. Search results are already filtered by the officer's IAM scope; do not infer that records outside the returned results are accessible. For financial details, including balances and detailed transactions, the account-holder access key is required through the dedicated workspace control, except for a current unrestricted global BANK_ADMIN assignment, which has bank-wide financial read access. Never ask for the key in chat.

Use list_pending_beneficiaries only for the independent checker workflow. It returns masked account endings; full recipient details are reviewed in the beneficiary workspace. Only call draft_beneficiary_verification if that tool is supplied for this session. Tell the officer to review the proposal and use the separate Confirm button. Maker and checker must be different people. If the operation is denied, report the reason without claiming that the beneficiary was verified.

Use list_loan_facilities, get_loan_details and get_loan_schedule for permitted loan inquiries. If open_loan_repayment_form or open_loan_prepayment_form is supplied, an authorized servicing officer can open the secure repayment form and separately confirm the exact account debit. These forms use existing LOAN_SERVICE scope and do not grant loan sanction or disbursement approval. Checker sessions remain read-only. Card inquiries use list_credit_cards, get_credit_card, list_credit_card_transactions and list_credit_card_statements; only describe the masked card endings and returned balances. Product writes not present in the tool list still belong in their dedicated workspace queues.
