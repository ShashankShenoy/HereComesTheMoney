AI ASSISTANT, STATEMENTS AND LOANS AUDIT
15 October 2026 | Local tests and read-only Oracle inspection

HISTORICAL AUDIT: The four findings below were subsequently repaired.
See ASSISTANT-STATEMENTS-LOANS-FIXES-2026-10-15.txt for the changes, validation,
approved staff configuration repair and remaining live-test limits.

RESULT
Four actionable findings remain. No application fixes or live business-data
changes were made in this audit. Existing loans and issued statements reconcile.
The real AI provider and fresh live statement generation were not exercised.

1. HIGH: LOAN SANCTION TERMS CAN FALL BELOW PRODUCT MINIMUMS
Confirmed through authenticated local controller tests, using a separate maker
and checker with valid sanction authority and an assessed application.

Reproduction A: product minimum INR 1,000; application INR 12,000 / 12 months;
checker sanctions INR 0.01 / 12 months. API returns HTTP 200 and APPROVED.
Reproduction B: product minimum tenure 12 months; application INR 12,000 /
12 months; checker sanctions INR 12,000 / 1 month. API again returns APPROVED.
Expected: reject sanction terms outside the product version's bounds.

LoanService.create validates the requested amount/tenure against the product.
LoanService.decide checks positive values, authority limits and that sanctioned
terms do not exceed the application, but does not enforce product minimums.
Relevant source: backend/loan-service/src/main/java/com/moneybags/loan/LoanService.java

Read-only inspection found no existing database facilities outside their current
product amount/tenure bounds. The reproductions used disposable H2 records only.

2. MEDIUM: CHECKER ASSISTANT CHAT AND MCP DISCOVERY ARE BLOCKED
Confirmed in two local controller tests. A BANK_CHECKER sees the assistant widget,
but POST /api/v1/assistant/chat and POST /api/v1/assistant/mcp (tools/list)
both return HTTP 403 / CHECKER_APPROVAL_ONLY before the assistant can respond.
BankCheckerWriteBoundary rejects these POST routes, including read-only requests.
The test model is stubbed; no provider call was required to reproduce the denial.
Relevant source: backend/shared/src/main/java/com/moneybags/iam/security/BankCheckerWriteBoundary.java
UI entry: frontend/app.js

3. MEDIUM: STAFF STATEMENT CONFIGURATION IS INCOMPLETE
Confirmed by Oracle SELECTs in an enforced READ ONLY transaction:
- No M10_STATEMENTS processing purpose exists.
- No approved WEB / STAFF masking profile exists.
- No approved STAFF narration catalogue entries exist.
Staff requests require a purpose; issuance selects an audience-specific approved
masking policy and approved narrations. Staff-assisted issuance therefore lacks
the configuration it needs. This audit did not attempt to approve or add policies.

Customer configuration has an approved WEB / CUSTOMER masking profile and four
effective en-IN narration types. Five existing customer statements are ISSUED;
their line counts, closing balances and running balances are consistent. One
additional request is AUTHORIZED, which is pending work rather than a failed issue.

4. MEDIUM: PREPAYMENT SETTINGS EXCEED SERVICING CAPABILITIES
All seven active loan products have PREPAYMENT_ALLOWED,
PARTIAL_PREPAYMENT_ALLOWED and FORECLOSURE_ALLOWED set to Y.
LoanServicingController only allocates payments to accrued due installments.
An early payment is rejected with HTTP 409 / LOAN_SERVICING_RULE and a message
that early prepayment requires a reschedule workflow. No loan reschedule or
foreclosure command exists in the implemented loan controllers.
This is a product-configuration/capability mismatch, not a balance discrepancy.
The early-payment rejection was reproduced in the isolated lifecycle test.
Relevant source: backend/loan-service/src/main/java/com/moneybags/integration/LoanServicingController.java

LIMITS AND DATA SAFETY
Automatic approval review rejected the combined live AI/statement action because
it used privileged accounts, sent account/tool data to the configured external
provider and created statement records. The user then selected local and
read-only testing. That rejected action was not executed or bypassed.

Oracle inspection used SET TRANSACTION READ ONLY followed by rollback. No login
or statement/read-audit records were created through the live app. No live loan
was approved, disbursed, repaid or otherwise changed. Only local audit tools,
evidence and this report were added. The unused live-test script was removed.

The app gateway at http://127.0.0.1:8091/actuator/health refused connections at
the final live availability check, and none of the expected app ports appeared
as listening. Existing app credentials and configuration were not changed.
Consequently current browser flows, external provider connectivity and fresh
Oracle statement generation remain unverified. Do not read this audit as a
complete live end-to-end pass.
