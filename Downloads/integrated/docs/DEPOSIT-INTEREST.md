# Savings interest and fixed deposits

## Enable on Oracle

1. Stop the Oracle demo backend and back up the application schema. Review `database/018-deposit-interest.sql` with the database owner, especially the new interest expense and term deposit liability GLs. Run it once from SQL*Plus as the application schema owner. From `Downloads/integrated`, run `@database/018-deposit-interest.sql` while connected as that owner. Oracle DDL commits as it runs; a failed run requires DBA review before retrying.
2. Confirm the `INTEREST` mappings for each active savings product version, and `TERM_DEPOSIT` mappings for each active fixed deposit version. The migration maps versions already active when it runs. Map subsequently activated versions before customer use. The service rejects missing or ambiguous mappings.
3. Set `DEPOSIT_INTEREST_ENABLED=true` in the backend environment, rebuild the backend JAR, and restart. Keep it false until migration and mapping checks are complete. On this workstation, the ignored `.env.ps1` read by `start-oracle-alpha.ps1` is the place for the setting.
4. In Product master, create a `DEPOSIT` product in INR. Add an interest rule with `FIXED`, `SIMPLE`, `AT_MATURITY`, an annual rate, a supported day-count basis and rounding mode. Add a Term rule with amount and month limits, plus `WEB` availability for the customer's branch and segment. Submit, independently approve, and activate the version. Set its GL mapping before opening deposits.
5. Sign in as a customer and open **Accounts**. An active savings/current account is needed to fund a fixed deposit. The screen lists eligible products and existing deposits. Savings interest credits are visible from the account's **Interest** action and in transactions/statements.

Savings interest posts on the first day of each month at 01:10 Asia/Kolkata for the preceding completed month. An administrator with `GL_POST` can retry or backfill an eligible completed period using `POST /api/v1/deposit-interest/runs?period=YYYY-MM`. The result reports each account as `POSTED`, `ALREADY_POSTED`, `NOT_CONFIGURED`, or `ERROR`; inspect errors and reconcile journals. An account without an approved interest rule returns `NOT_CONFIGURED` and receives no posting. When an approved rule begins during a month, only its configured days accrue. The rollout date prevents calculation for earlier days. There is no accrued interest liability posted between monthly credits.

Fixed deposits mature daily at 01:30 Asia/Kolkata. An administrator can retry `POST /api/v1/term-deposits/{id}/mature` for a due deposit. Funding and maturity use balanced GL journals. The fixed rate, basis and expected payout are stored with each contract, so later product changes do not reprice it. Early withdrawal, partial withdrawal, automatic renewal, tax withholding and alternative payout accounts are not implemented. The funding account must remain active through maturity.
